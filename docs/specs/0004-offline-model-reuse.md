# 0004. Повторные запуски без обращения к Hugging Face

- **Статус:** Implemented
- **Дата:** 2026-11-11
- **Тип:** ретроспективная спека (восстановлена по коммиту)
- **Коммит:** `d3acb64` — `fixed model download`
- **Связанные спеки:** 0003, 0005, 0006
- **Затрагиваемые файлы:** `kokoro_tts/synthesizer.py`

## Контекст и проблема

После переноса модели в `model/` каждый запуск всё ещё вызывал
`snapshot_download`, то есть обращался к Hugging Face даже когда все файлы
уже были на месте. Это мешало работать офлайн и замедляло повторные запуски.

Дополнительно `KModel` мог сам сходить за `config.json` на HF Hub, даже если
локальная копия уже есть.

## Цели и не-цели

**Цели:**

- проверять локальную готовность модели до обращения к сети;
- не скачивать ничего, если все нужные файлы на месте;
- корректно обновлять модель при смене `--revision`;
- передавать `KModel` локальный `config.json`.

**Не-цели:**

- докачка частично скачанных файлов по отдельности;
- проверка хешей и целостности;
- автоматическое удаление устаревших файлов.

## Пользовательский сценарий

```bash
python main.py input/example.md   # первый запуск: модель скачивается
python main.py input/example.md   # второй запуск: "Модель уже скачана", сеть не нужна
python main.py input/example.md --revision <новый-коммит>  # модель обновится
```

## Требования

- **FR-1.** `_required_files()` перечисляет минимум для выбранного голоса:
  чекпоинт, `voices/<voice>.pt`, `ru_g2p.py`, `config.json`, `espeak-data`.
- **FR-2.** `_model_ready()` возвращает `True`, только если все обязательные
  файлы существуют.
- **FR-3.** Если `--revision` не задан и файлы на месте, `snapshot_download`
  не вызывается; печатается «Модель уже скачана».
- **FR-4.** Если `--revision` задан, дополнительно сверяется маркер
  `.downloaded_revision`; при несовпадении модель скачивается заново и маркер
  перезаписывается.
- **FR-5.** `KModel` получает локальный путь к `config.json`, чтобы не ходить
  за ним на HF Hub.
- **FR-6.** При отсутствии любого обязательного файла модель скачивается
  заново.

## Критерии приёмки

- **AC-1.** Дано полностью скачанная модель и отсутствие `--revision`, когда
  запускается синтез, тогда `snapshot_download` не вызывается и печатается
  «Модель уже скачана».
- **AC-2.** Дано скачанная модель и тот же `--revision`, когда запускается
  синтез, тогда сеть не используется (маркер совпадает).
- **AC-3.** Дано скачанная модель и другой `--revision`, когда запускается
  синтез, тогда модель скачивается заново, маркер обновляется.
- **AC-4.** Дано удалённый `voices/<voice>.pt`, когда запускается синтез,
  тогда модель скачивается заново.
- **AC-5.** Дано второй запуск без сети, когда все файлы на месте, тогда
  синтез работает офлайн.

## Крайние случаи и ошибки

| Ситуация | Ожидаемое поведение |
|---|---|
| Нет маркера при заданном `--revision` | Модель скачивается, маркер создаётся |
| Маркер есть, но файлов не хватает | Модель скачивается заново |
| `--revision` не задан, файлы есть | Сеть не используется |
| Удалить `model/` | Следующий запуск скачает модель заново |
| Сменить голос | Проверяются файлы нового голоса |

## Решения и альтернативы

- **Решение:** проверять фиксированный список файлов, а не только каталог.
  **Почему:** частично скачанная модель должна докачиваться.
- **Решение:** маркер `.downloaded_revision` только для явного `--revision`.
  **Почему:** без ревизии достаточно наличия файлов; маркер не нужен.
- **Решение:** передавать `config` локальным путём в `KModel`.
  **Почему:** иначе библиотека может обратиться к HF Hub в обход проверки.
