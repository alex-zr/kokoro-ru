## Контекст и проблема

Нужна CLI-утилита, которая берёт Markdown-файл, очищает разметку, разбивает
текст на предложения и озвучивает его русской моделью kokoro-ru. На момент
первого коммита других способов получить аудио из `.md` в проекте не было.

Спека ретроспективная: она описывает поведение исходной версии, а не
предварительную договорённость. Обсуждения, предшествовавшие коммиту, в
репозитории не сохранились.

## Цели и не-цели

**Цели:**

- запуск из терминала и PyCharm без сборки и фреймворков;
- очистка Markdown без тяжёлых зависимостей;
- выбор голоса, скорости и устройства;
- сохранение `.wav` и опциональная конвертация в `.mp3`;
- режим `--clean-only`, работающий без модели.

**Не-цели (на этом этапе):**

- пакетная обработка папок;
- офлайн-повторные запуски без обращения к Hugging Face;
- `.mp3` по умолчанию и удаление промежуточного `.wav`;
- сохранение результата рядом с исходником;
- один аргумент вместо `--batch` (появится позже).

## Пользовательский сценарий

```bash
python main.py                                   # input/example.md -> output/example.wav
python main.py input/notes.md --voice dima
python main.py input/notes.md --speed 0.95 --mp3
python main.py input/notes.md --clean-only       # только очистка, модель не нужна
```

Рядом с аудио остаётся очищенный `.txt` для проверки того, что будет
прочитано вслух.

## Требования

- **FR-1.** Позиционный аргумент — путь к одному `.md`; без аргумента
  используется `input/example.md`.
- **FR-2.** Если файл не найден, печатается сообщение с путём и код возврата
  1; модель не загружается.
- **FR-3.** Текст очищается `clean_markdown`; числа заменяются словами, если
  не передан `--no-numbers`.
- **FR-4.** Очищенный текст сохраняется в `.txt` рядом с будущим аудио.
- **FR-5.** `--clean-only` завершает работу после сохранения `.txt`, не
  импортируя `torch`, `kokoro` и `soundfile`.
- **FR-6.** Если после очистки текст пуст, печатается сообщение и код 1.
- **FR-7.** Голос выбирается из `VOICES` (`sveta`, `masha`, `dima`),
  по умолчанию — `masha`; доступны `--speed`, `--device`, `--revision`.
- **FR-8.** Модель скачивается через `snapshot_download`; чекпоинт и голосовой
  пак загружаются из репозитория модели.
- **FR-9.** Синтез идёт по абзацам и предложениям; слишком длинные фразы
  делятся через `split_in_half`; слова вне словаря выводятся списком.
- **FR-10.** Аудио сохраняется как `.wav` с частотой 24 кГц; путь по
  умолчанию — `output/<имя>.wav`, `-o` переопределяет его.
- **FR-11.** С `--mp3` дополнительно создаётся `.mp3` через `ffmpeg`;
  если `ffmpeg` не найден, печатается подсказка, `.wav` остаётся.

## Критерии приёмки

- **AC-1.** Дано отсутствие входного файла, когда запускается CLI, тогда
  печатается «Файл не найден» и код 1.
- **AC-2.** Дано Markdown с заголовками, ссылками, кодом и таблицами, когда
  вызывается `clean_markdown`, тогда результат совпадает с ожидаемым текстом
  (точное сравнение строк).
- **AC-3.** Дано длинный абзац, когда вызывается `split_sentences` /
  `split_in_half`, тогда предложения и половины собираются обратно в исходный
  текст.
- **AC-4.** Дано `--clean-only`, когда модели нет в окружении, тогда команда
  завершается успешно и создаёт `.txt`, не пытаясь скачать модель.
- **AC-5.** Дано `--mp3` и установленный `ffmpeg`, когда синтез завершён,
  тогда рядом с `.wav` появляется `.mp3`.
- **AC-6.** Дано `--mp3` без `ffmpeg`, когда синтез завершён, тогда печатается
  подсказка `brew install ffmpeg`, а `.wav` остаётся.

## Крайние случаи и ошибки

| Ситуация | Ожидаемое поведение |
|---|---|
| Пустой после очистки текст | Сообщение, код 1, синтез не запускается |
| Слишком длинное слово | Печатается предупреждение, фрагмент пропускается |
| Слова вне словаря G2P | Выводятся списком после синтеза |
| Нет `ffmpeg` | Остаётся `.wav`, печатается подсказка |
| `--clean-only` без `torch` | Работает: тяжёлые импорты ленивые |

## Решения и альтернативы

- **Решение:** тяжёлые импорты внутри функций.
  **Почему:** `--clean-only` и тесты должны работать без модели.
- **Решение:** `markdown_cleaner` и `chunking` без внешних зависимостей.
  **Почему:** их можно тестировать отдельно от синтеза.
- **Решение:** `ru_g2p.py` из репозитория модели импортируется как код.
  **Почему:** фонетика и ударения поставляются вместе с моделью.
  **Риск:** код модели может меняться; для воспроизводимости есть
  `--revision`.
- Причины выбора голоса `masha` по умолчанию в истории не зафиксированы.
