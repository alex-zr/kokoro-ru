# 0008. Аудио рядом с исходником и удаление временного текста

- **Статус:** Implemented
- **Дата:** 2026-11-11
- **Тип:** ретроспективная спека (восстановлена по коммиту)
- **Коммит:** `08e3cfe` — `default output folder by input folder`
- **Связанные спеки:** 0002, 0005, 0007, 0009
- **Затрагиваемые файлы:** `main.py`, `tests/test_batch.py`, `README.md`

## Контекст и проблема

Раньше результат по умолчанию попадал в `output/<имя>.wav` в корне проекта.
Это неудобно: аудио оказывалось далеко от исходного Markdown, а одинаковые
имена файлов из разных папок могли перезаписывать друг друга. Кроме того,
очищенный `.txt` оставался после каждой озвучки как мусор.

Нужно сохранять результат рядом с исходником и убирать временный текст после
успешного синтеза.

## Цели и не-цели

**Цели:**

- по умолчанию писать аудио в папку исходного `.md`;
- имя результата совпадает с именем исходника, меняется только расширение;
- сохранить `-o` для одиночного файла;
- удалять временный `.txt` после успешной озвучки;
- оставлять `.txt` при `--clean-only`.

**Не-цели:**

- зеркалирование структуры папок в отдельный корень;
- переименование файлов по заголовкам;
- настройка отдельного места для временных файлов.

## Пользовательский сценарий

```bash
python main.py ~/Documents/notes/chapter.md          # -> chapter.mp3 рядом
python main.py ~/Documents/notes/chapter.md -o /tmp/chapter.wav
python main.py ~/Documents/notes/chapter.md --clean-only  # chapter.txt остаётся
```

## Требования

- **FR-1.** Без `-o` путь аудио — `source.with_suffix(".wav")`, затем при
  необходимости `.mp3`.
- **FR-2.** Расширение исходника `.markdown` тоже заменяется на `.wav`/`.mp3`.
- **FR-3.** `-o` переопределяет путь только для одиночного файла.
- **FR-4.** В папке (пакетный режим) `-o` запрещён.
- **FR-5.** Временный `.txt` создаётся рядом с аудио для проверки очистки.
- **FR-6.** После успешной озвучки временный `.txt` удаляется, печатается
  сообщение об удалении.
- **FR-7.** При `--clean-only` `.txt` остаётся как результат.
- **FR-8.** Если очистка дала пустой текст или синтез упал, `.txt` не
  удаляется.

## Критерии приёмки

- **AC-1.** Дано `notes/example.md` без `-o`, когда вычисляется путь аудио,
  тогда получается `notes/example.wav`.
- **AC-2.** Дано `notes/example.markdown`, когда вычисляется путь аудио,
  тогда получается `notes/example.wav`.
- **AC-3.** Дано `-o /tmp/custom.wav` и один файл, когда вычисляется путь,
  тогда получается `/tmp/custom.wav`.
- **AC-4.** Дано папка и `-o`, когда запускается CLI, тогда печатается
  запрет и код 1.
- **AC-5.** Дано успешная озвучка, когда она завершена, тогда `.txt`
  отсутствует, а аудио на месте.
- **AC-6.** Дано `--clean-only`, когда команда завершена, тогда `.txt`
  существует.

## Крайние случаи и ошибки

| Ситуация | Ожидаемое поведение |
|---|---|
| Имя с несколькими точками | Меняется только последнее расширение |
| `-o` без родительской папки | Папка создаётся при сохранении |
| Синтез упал | `.txt` остаётся для диагностики |
| `--clean-only` | `.txt` остаётся, аудио нет |
| Папка только для чтения | Ошибка записи, код 1 |

## Решения и альтернативы

- **Решение:** результат рядом с исходником.
  **Почему:** аудио и Markdown остаются вместе; меньше конфликтов имён.
  **Альтернатива:** общая папка `output/`.
  **Почему отвергнута:** файлы далеко от источника, возможны коллизии.
- **Решение:** удалять `.txt` только после успешного синтеза.
  **Почему:** при ошибке текст нужен для разбора.
- **Решение:** `-o` только для одного файла.
  **Почему:** для пачки непонятно, как раскладывать файлы в одну папку.
